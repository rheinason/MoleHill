# MoleHill Penpot reference

For a local Docker installation, see [`selfhost/README.md`](selfhost/README.md).
Approved design directions, unresolved polish and the next review decisions are
tracked in the [Rhino UI design backlog](../../docs/ui-backlog.md).

Build an editable native Penpot design file from the current Rhino UI source:

```powershell
cd tools/penpot
npm ci --ignore-scripts
npm run build
```

Open [output/preview.html](output/preview.html) to browse the rendered screens.
Import [output/MoleHill-UI.penpot](output/MoleHill-UI.penpot) using **Import files**
in the target Penpot project. The file is generated by the official
[`@penpot/library`](https://github.com/penpot/penpot/tree/develop/library) package.
Penpot's [import guide](https://help.penpot.app/user-guide/export-import/export-import-files/)
describes the dashboard workflow.

## Contents

- Foundations: 12 semantic colour roles, each with light/dark values in native
  Penpot token sets, plus the Core Terrain Spectrum gradient and linked typography,
  spacing and size specifications from `UiMetrics`.
- Editable control and action examples, card main components, and linked screen
  instances. Universal action icons are vectors; badge/tab icons are the source PNGs.
- 54 main components: 39 real card types and 15 shared field families. Theme,
  width, units and values are instance overrides rather than separate assets.
  Cards and rows use flex layout; standard chrome references colour tokens.
  Specialised analysis/data colours remain literal source values, preserving the
  reference appearance without adding dozens of palette assets.
- All 39 registered modifier, object, analysis and annotation types in light/dark
  card atlases. Legacy markers are excluded because they have no authoring tab.
- Thirty panel boards: all five tabs at 240, 320 and 480 logical pixels, in both themes.
  Panel shells and width/state compositions are regular editable frames containing
  linked shared fields; the card atlases contain linked card instances.
- Expanded settings/status, empty, warning and rebuild states.
- Twenty-eight source-backed dialog boards across both themes: layer templates,
  role checklists, field codes, survey import, block pickers, zone layers, input
  validation, slow-build warnings, terrain/scan extraction, scan advanced settings,
  curve inspection and route relaxation; plus the sculpt toolbar.

The generator leaves the application source and runtime behaviour unchanged.
`output/` and `node_modules/` are local generated artifacts, excluded from git.
The checked-in generator and npm lockfile make them reproducible from a source revision.

## Accuracy and verification

Labels, units, descriptor metadata, badge assets, theme colours and fixed metrics
come from the working tree, including any uncommitted UI edits. The inventory
records descriptor paths, SHA-256 hashes and full row declarations. `visibleWhen`
rows are tagged `conditional`; atlases intentionally include mutually exclusive
rows for design reference. The screens select representative expanded/collapsed
states and omit conditional rows rather than executing the Rhino view-model.

Layout is an editable reconstruction of Eto's layout rules. It is **not a live
capture of every native widget**. Standard widgets use vector outlines;
Source Sans Pro is the portable Penpot font in place of Rhino's system font.
Scalar defaults are read from model definitions, including base-type initializers.
Document-dependent references, result counts, histogram bins and mapped ranges are
illustrative. The continuous Terrain Spectrum gradient uses the Core preset stops.
Character-based breakpoints depend on the active font; the reconstruction uses
approximately 7 pixels per character. Dialog control vocabulary/order comes from
the corresponding source constructor; populated grids/charts contain example data.

`npm run build` verifies positive geometry, parent/child links, component references
and shape references, exports through Penpot's library, then renders screen SVGs
with resvg. `output/validation.json` reports the exact coverage. This validates
generation, **not native import or component propagation in a running Penpot**.
The self-hosted installation imports the file and verifies its counts through
Penpot's native API; see `selfhost/project.local.json`. `selfhost/review.mjs` audits
the imported geometry/links/styles and obtains native PNGs through Penpot's export
service. Interactive editor gestures and live propagation of component edits have
not been exercised through the browser. Regeneration resets the output report until
a new import is verified.

After import, inspect all pages for font substitution, select a screen card and
use **Go to main component**, and change a title in a main component to verify
that its instances update. Compare the 240/320/480 boards against the same widths
in Rhino before treating a proposed visual change as accepted.

## Updating the reference

`node tools/penpot/selfhost/prototype-triangulate.mjs --section-along-curve`
exports Step 32, adapting the simplified workflow to Section Along Curve with
distinct Sample Interval and Distance Interval controls.

`node tools/penpot/selfhost/prototype-triangulate.mjs --section-line` exports
Step 31: Section Line input and directly visible Section Marks, with Section
Annotation retaining its collapse control.

`node tools/penpot/selfhost/prototype-triangulate.mjs --section-cut` exports
Step 30: simplified Section Cut versus the preserved reference at 400 px, and
collapsed/expanded proposals at 224 px, in both themes. It keeps Section Cut's
direct cut curves, tick controls and automatic one-row placement semantics.

`node tools/penpot/selfhost/prototype-triangulate.mjs --cross-section-comparison`
exports Step 29, showing Off / Original Terrain and Another Terrain / Rhino
Geometry. Shading starts enabled in the proposed active comparison states.

`node tools/penpot/selfhost/prototype-triangulate.mjs --cross-section-expanded-annotations`
exports Step 28, showing Plan Annotation and Section Annotation fully expanded,
plus an example with Layout Overrides open. Comparison remains Off.

`node tools/penpot/selfhost/prototype-triangulate.mjs --cross-section-paths`
exports Step 27, applying the approved Paths label to the Cross-Sections input.

`node tools/penpot/selfhost/prototype-triangulate.mjs --cross-section-picked-pill`
exports Step 26, with Pick Point becoming a Picked pill plus × clear action;
clearing restores automatic placement.

`node tools/penpot/selfhost/prototype-triangulate.mjs --cross-section-aligned-inputs`
exports Step 25, aligning Cross-Sections control right edges while numeric values
remain left-aligned.

`node tools/penpot/selfhost/prototype-triangulate.mjs --simple-cross-sections`
exports Step 24: proposed simple Cross-Sections card with optional comparison and
one Pick/Auto insertion row. Automatic column selection is proposed, not verified
current product behaviour; native pick/cancel still requires runtime testing.

`node tools/penpot/selfhost/prototype-triangulate.mjs --contour-flush-rows`
exports Step 23, with Contours settings on one property grid and group spacing
instead of extra indentation. Step 22 remains available for comparison.

`node tools/penpot/selfhost/prototype-triangulate.mjs --contour-hierarchy` exports
Step 21, showing Contours with Labels off/on and Appearance expanded. The checkbox
reveals dependent settings; there is no separate Labels expansion control.

`node tools/penpot/selfhost/prototype-triangulate.mjs --compare-header-groups`
exports Step 20: current versus Blender-style grouping in paired columns, for
collapsed/expanded headers at wide/narrow sizes and in both themes.

`node tools/penpot/selfhost/prototype-triangulate.mjs --bare-type-icon` exports
Step 19, comparing the same card type glyph with and without its background plate.

`node tools/penpot/selfhost/prototype-triangulate.mjs --borderless-actions`
exports Step 18, comparing outlined and borderless resting header actions with
identical smaller control sizes. Hover/focus behaviour requires native validation.

`node tools/penpot/selfhost/prototype-triangulate.mjs --compact-controls` exports
Step 17: 14 px type badge / 10 px glyph and 18 px header actions. Earlier pages
are preserved. Exact native Rhino Layers toolbar dimensions remain unverified.

The separate Step 16 header comparison uses measured lowercase x-height and a
16 px type badge with a 12 px glyph. Run
`node tools/penpot/selfhost/prototype-triangulate.mjs --xheight-headers` to export
the preserved comparison page. Font probes, calibration and read-only PNG audit
are under `.artifacts/penpot-selfhost/design-step-16/`. These font-specific
prototype offsets require fresh measurement in Eto.

`inventory.mjs` reads the descriptor factories without loading Rhino. It is a
small C# source reader, not a full compiler. Bespoke UI hooks, shared catalogs and
layout adjustments are composed in `build.mjs`; update those when the corresponding
panel partial changes. Secondary workflows live in `dialogs.mjs`. A new schema factory should get an explicit drawing branch
in `row()` rather than silently masquerading as a numeric input.

The reference file is a starting point for design work. Rebuilding creates a fresh
file; it does not merge changes made by designers in Penpot. Keep the imported
design file as the editable design master, and regenerate into a separate reference
file when comparing newer application behaviour.

To import a revised generated reference into the existing local project while
preserving the previous file:

```powershell
node ./tools/penpot/selfhost/init-project.mjs --refresh
```

Identical archive hashes are verified without creating duplicates. Do not regenerate
over a designer-edited reference expecting their changes to merge automatically.
